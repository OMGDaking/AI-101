# Course brief excerpts — selected practice input

## Step 6. Build the Canvas map

In Obsidian, make `process-map.canvas`. Add one node per step, three to five steps, connected by arrows in order. Mark which steps the model does and which step is your human check. Link each Canvas node to its step file.

Done means: A partner can follow your map from input to output without asking you questions.

## Step 7. Write the start file and step files

Write `00-start-here.md`: the goal, the order to follow, the rules, and what stays your decision. Then write one step file per node, each with: what starts it, what it does, what good looks like, and how you will check it.

Done means: Someone who has never met you could read the folder and know what to do.

## Step 8. Run it

In Claudian, point the model at your folder and tell it to follow `00-start-here.md`. Let it work one step at a time. After each step, check the result before it continues. Save the first-run output in `outputs/`. Make an AI Use Log entry for every step.

Done means: The first run is saved, and every step is logged with a date.

## Step 9. Name the intent gap

Put the first-run output next to `intent.md` and finish four sentences: I intended… The model did… The clearest gap is… I think the cause is in step file…

Done means: You know which file to fix and what to ask critique about.

## Step 10. Take critique — Class 7

In groups of three, show your map, your step files, and your first run. Peers say what they noticed first, then suggest. Write everything down. Label each note keep, change, reject, or unsure. Make `feedback.md`.

Done means: You have specific notes tied to specific steps or files.

## Step 11. Fix your directions and run again — Class 7

Change what the gap and feedback point to: a step file, the start file, the map, or a human check. If your first run was strong, do not invent a flaw: stress-test instead with harder input, one tighter rule, or the human check moved earlier. Run the workflow again. Save the new output separately. Keep the first run.

Make `decision-note.md`: the gap you found, what you changed, why, and what is still unresolved.

Done means: Someone can compare the two runs and see what your change fixed.
